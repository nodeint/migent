# Implementation

Implement only the task or plan phase selected by the user.

## Implement

- Follow the repository's contribution and branch rules when present.
- Read required inputs. Stop if they are missing or inconsistent.
- Confirm scope, acceptance criteria, and checks against repository evidence.
- Treat issue proposals as proposals. Ask about consequential ambiguity.
- Follow the approved design and plan. Address prior comments or explain why not.
- Without a design, investigate the root cause. Seek decisions on major structural or contract choices.
- Reproduce bugs before editing. Ask how to proceed if reproduction fails.
- Implement with relevant tests and documentation. Preserve unrelated work.
- Seek a decision before changing the agreed scope or solution.
- Follow repository baseline requirements and run the selected scope's checks.
- On revision, address required findings and rerun affected checks.

## Report

- Use the requested report location; otherwise report in the conversation.
- State changes, affected paths, commands, results, deviations, and blockers.
- Separate baseline results, planned checks, and completed checks. Note anything unverified.
- End saved reports with References: required inputs and their purpose, including the issue if available.
- Keep supplied input paths or links. Use repository-relative paths for repository files.
- Write None when there are no references.
