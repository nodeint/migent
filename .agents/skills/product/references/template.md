# PRD template

Keep all headings and their order. Replace placeholders with concise content.
For inapplicable sections, state why. Resolve questions before completing the specification.

```markdown
# PRD: <outcome>

## Problem statement & user value

<Who is affected, what problem is solved, and what value is delivered.>

## Target users & use cases

- UC1: <Primary use case description, target user, and trigger.>

## User experience & interaction flow

<CLI command syntax, flags/arguments, prompts, progress indicators, output formats (plain text, JSON), and error feedback.>

## Functional requirements & business rules

- FR1: <Functional requirement, validation rule, default behavior.>

## Scope & non-goals

### In-scope
- <Specific capability included in this scope.>

### Non-goals
- <Explicitly excluded capabilities or deferred features.>

## Edge cases & user feedback

- <Unusual inputs, cancellation, missing resources, and how the system informs the user.>

## Acceptance criteria

- AC1: <Observable criteria from user/consumer perspective.>

## References

- <Source path>: <Purpose.>
```
